# StackNest 部署

使用 `stacknest-deploy` 完成静态项目的自动部署。CLI 负责分片、文件校验、续传及有限重试；不用重新实现上传协议。

## 确定本次操作

- “给我预览”“先看看”：只执行 `upload`，返回预览链接。
- “直接上线”“更新正式网站”：用户已授权正式发布；上传成功后发布这次产生的确切版本，无需重复确认。Token 也须有发布权限。
- 未说明是否正式上线时，默认生成预览，并说明正式站点尚未变化。
- “发布刚才那个预览”：使用该次上传回执中的 `draftId`、`expectedId`，不要重新上传文件或盲目发布最新草稿。没有回执且无法确定用户指定的版本时，先澄清目标。
- 查询项目或版本时执行 `status`，不产生上传或发布。
- “继续修改刚才的预览”“更新这个待发布版”：用户已授权替换该草稿，使用对应回执的 `draftId` 作为 `upload --replace-draft`，默认仍只预览。目标不明确时先澄清，不自动选择最新草稿。

## 首次配置或配置失效

首次使用时由 AI 引导配置，不要求用户先手动编辑 Markdown。已配置的项目直接复用有效设置，只询问缺失或失效的项。项目级 Token 已绑定唯一项目，项目名称、ID、slug 和站点网址都不是首次连接的必填输入；先用 Token 查询，再展示识别结果。

1. 读取 [本机配置](references/local-config.md)。优先级为本次用户指定、用户项目的明确配置、本机默认值。也可使用已提供的 `STACKNEST_URL` 和 `STACKNEST_DEPLOY_TOKEN`；检查凭据环境变量是否存在即可，不打印其值。不搜索其他项目的凭据。
2. 检查已配置的 CLI 路径；缺失或已失效时，先在 PATH 中查找 `stacknest-deploy` / `stacknest-deploy.exe`，不要遍历整台电脑。使用 `version` / `--help` 确认可执行，需要 `v1.0.0-rc.2` 或更新的兼容版本。
3. 将仍缺少的信息合并为一次简短询问。下面是完整缺省时的示例；实际删去已知项：

   > 首次连接 StackNest，请提供管理端完整地址和项目 Token 文件路径。CLI 如果已经安装，请提供路径；尚未安装可以回复“帮我安装”。项目由 Token 自动识别，不用填写项目名或 slug。只需要凭据文件路径，不要发送 Token 内容。

4. 用户需要协助安装 CLI 时，识别当前系统和 CPU 架构，从 [发布页](https://github.com/zby909/stack-nest-server/releases) 选择兼容版本，校验配套 SHA-256，解压到用户可写的本地工具目录，记录绝对路径，不强制修改系统 PATH 或覆盖已有工具。用户尚未创建 Token 时，引导其在“项目详情 → 设置 → 自动部署”创建并保存到仓库外文件；需要正式发布时勾选相应权限。未拿到对应配置前可以准备文件，不能上传到猜测的目标。
5. 凭据通过 `--token-file` 或已有环境变量传入，让 CLI 读取。不要输出 Token、把它拼进命令行或存入 Skill、源码、Git 和聊天。远程地址使用 HTTPS；HTTP 仅用于本机回环隧道。拿到管理地址和凭据后立即执行 `status`，从返回的 `id`、`slug`、`siteUrl` 自动识别项目；`status` 不需要项目名称或 `--slug` 参数。用户已为本次任务提供一个 Token 时，以它绑定的项目为目标，展示结果即可，不再要求填写或额外确认项目名。只有返回的身份与用户明确指定或此前保存的目标不一致，或有多个可用凭据但无法判断用哪个时，才澄清目标。认证失败时修复凭据，不用追问项目名代替验证。一个 Token 仅绑定一个已有项目；新项目要由用户在后台创建。
6. 验证通过后，默认在用户私有安装副本的 `references/local-config.md` 记住 CLI 路径、管理端 URL，以及查询到的项目 ID、slug、siteUrl 和对应 Token 文件路径或“使用环境变量”。这些项目字段来自返回值，不要求用户补填显示名称。只保存路径及身份信息，不保存 Token 原文；告诉用户保存位置。保留其他项目配置，不能把一个项目的 Token 当作所有项目的默认值。用户要求仅本次使用时不保存。Skill 位于受 Git 跟踪的目录或只读目录时，使用用户另行指定的私有配置位置；没有此位置则仅本次使用并说明，不改共享模板，也不阻断已经授权的部署。

换电脑后路径不存在、Token 到期或被撤销时，只修复对应配置，不让用户重填全部信息。仅要求配置 Skill 时，以 `status` 验证成功作为完成条件，不自动上传或发布。

## 准备文件

确认上传的是用户指定的成品。支持 HTML / HTM / ZIP / RAR，单文件不超过 90 MiB。单个 HTML 名称不限，会作为 `index.html`；依赖本地 CSS、JS、图片时应将相关资源连同 `index.html` 打包。前端源码项目须先执行它自身的构建步骤，再打包输出目录内容；不把源码、`.env`、凭据或整个工作目录打包。

本 Skill 只处理现有静态项目的部署；创建、删除、回退、丢弃草稿、管理 Token 和 Docker 应用仍走平台对应功能。

## 调用 CLI

在用户项目目录执行，让默认续传收据留在该项目。下面的变量来自已确认的路径和配置；按当前终端正确传递参数，不拼接可执行的命令字符串。

PowerShell 示例：

```powershell
& $cli status --url $url --token-file $tokenFile
& $cli upload --url $url --token-file $tokenFile --file $file --notes $notes
& $cli publish --url $url --token-file $tokenFile --draft-id $draftId --expected-id $expectedId
```

Bash 示例：

```bash
"$cli" upload --url "$url" --token-file "$tokenFile" --file "$file" --notes "$notes"
```

使用已注入的 `STACKNEST_DEPLOY_TOKEN` 时省略 `--token-file`。其他子命令的参数相同。`publish` 仅在本次任务包含正式发布时执行。

- 检查退出码；非零就停止依赖该结果的操作。标准输出是 JSON，进度在标准错误输出；不要合并两者再解析 JSON。
- `upload` 默认生成预览，并返回 `projectId`、`slug`、`draftId`、`expectedId`、`previewUrl`、`siteUrl`、`status`。更新说明最多 4096 字节。
- 保留该次返回值供发布使用。只有这份回执的 `expectedId` 为空时，发布参数才传字面值 `none`；非空时原样传入。不能为消除冲突而改成查询到的新版本编号。
- 上传仅返回 `status=preview` 时，使用其 `previewUrl`；重复执行同一次已发布上传可能返回 `status=published`，此时核对 `siteUrl` 和版本，不生成新草稿。

## 中断、草稿和重试

- 更新待发布版需要后端和 CLI 均为 `v1.0.0-rc.4` 或更新的兼容版本；先用 CLI `--help` 确认支持 `--replace-draft`。缺少能力时协助配套升级，不用“先丢弃旧草稿再上传”代替。将确切旧编号附在原上传命令后，例如 `upload --file guide.html --replace-draft dep-旧编号`。旧版及正式站点在失败时保留；成功使用新回执和新预览地址，旧预览失效。后续发布使用新回执的编号。
- 未完成上传保留 24 小时。默认收据为当前目录的 `.stacknest-upload-*.json`；保持同一工作目录、文件和参数才能续传。上传期间不修改文件，成功后也保留收据以便幂等确认。
- CLI 已内置有界重试。遇到网络错误且连接已恢复，可以用相同命令再试一次；仍失败就报告已确认的状态，不在外层无限循环。
- 同一项目只能有一个草稿。普通上传仍禁止覆盖。已授权替换的草稿发生变化、已有其他草稿、版本冲突或恢复信息不匹配时停止；不改成新的草稿编号、丢弃草稿、改变正式版基线或删除收据来强行覆盖。替换失败后续传仍使用原 `--replace-draft` 和原文件参数。
- 401 / 403、文件校验错误、容量不足等情况不自动重试。说明实际错误及对应处理，不展示凭据。
- 默认按文件和参数生成新收据，无需手动指定 `--state`。如果用户指定固定状态文件，新文件必须使用新的状态文件。
- 凭据和 `.stacknest-upload-*.json` 不提交到 Git；尊重用户项目现有的忽略规则。

## 验证与交付

访问返回的预览或正式 URL，核对 HTTP 状态和本次内容的可辨识特征，例如标题或修改的文字。不能访问时如实区分“上传／发布成功”和“访问验证未完成”，不要因为验证失败再次发布。

返回实际项目、预览或正式状态、访问链接及必要的版本编号。预览地址可由持有链接的人访问；只上传预览时明确正式站点未变化。正式发布后项目原网址保持不变。
