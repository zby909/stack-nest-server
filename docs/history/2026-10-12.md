## 已修复的问题

| 问题                                    | 确认方式与修复                                                                                                                                                       |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 版本预览没有严格限制域名后缀            | 用真实部署版本复现多级主机名读取预览，以及错误后缀落入管理路由。现在仅允许单级版本标签加配置的基础域名或 localhost；整个预览命名空间先由 Go 拦截，错误主机返回 404。 |
| Docker 更新期间日志遗漏生效配置的敏感值 | 更新保存候选配置后，旧容器仍可能提供日志。现在同时遮盖候选和生效配置的环境值、仓库密码，旧密文不可读时拒绝返回日志；保留最长值优先、一次替换的重叠处理。             |
| SSH 回环入口对未知 Host 返回管理页      | 实际入口验收确认此回退。Nginx 现在只接受管理回环主机和合法项目 localhost 域名，其他主机返回 404；补充真实 HTTP 请求回归。                                            |

前两项新增回归在修复前能够复现失败，修复后通过。SSH 入口的遗漏由部署验收捕获，更新流程成功回退，再按修复后的模板完成更新。

## 实例验收

修复已更新至现有实例。数据库中的 3 个用户、3 个静态项目、5 条版本记录和 1 个 Docker 应用保持原样，业务表及静态文件摘要一致，数据库和用户应用容器未重建。网络配置保持不变，doctor 与网络保护自检通过；更新前已完成一致性备份。

正常公网 HTTPS 请求验证管理页面、测试页、静态项目及 Docker 应用可达，匿名管理 API 返回 401，未知域名返回 404。正式静态响应保持 `no-cache`，条件请求返回 304；经过 Cloudflare 的 HTML 本次使用 `Last-Modified` 校验，源站同时验证了 ETag 协商。

真实邮件送达、DNS 切换、业务数据库恢复和目标手机浏览器仍应按 [需求与验收](../REQUIREMENTS.md)在各实例核对。版本预览目前仍是公开链接；应用镜像回退不回退业务数据，日志遮盖也只覆盖平台已知的配置值。
