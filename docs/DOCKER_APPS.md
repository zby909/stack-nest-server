# Docker 应用首版部署说明

当前功能以“仓库镜像地址 + 单个 HTTP 服务”为范围，不在服务器构建用户源码。

## 部署权限与服务边界

增加独立的 `runner` 容器，用平台 Go 二进制提供受限接口：

- 运行器使用 root 用户，持久挂载 `/var/run/docker.sock`。该 socket 实际拥有控制宿主 Docker 的高权限；限制 API 参数不能消除运行器本身被入侵的风险。
- 后台 API 不挂载 Docker socket，仅以 UID 10001 访问私有 Unix socket `/run/stacknest-runner/control.sock`。
- 运行器不监听 TCP。控制目录和 socket 限制到平台用户，用户应用不挂载它们。
- 运行器仅操作带有本实例及应用编号标签的容器、网络；不能经公开应用接口指定任意容器编号或主机目录。
- 运行器读取 Docker 存储文件系统的剩余空间；将 Docker 存储根目录只读挂载为 `/docker-storage`。
- 运行器本身限制为 96 MiB、0.5 CPU、64 PID，根文件系统只读，仅开放管理数据目录所需 capabilities。启用 XFS 数据配额时只向受信任 Runner 增加 SYS_ADMIN，用户应用不获得该权限。

用户已于 2026-10-09 授权独立运行器使用宿主 Docker socket。Compose、Nginx、备份及迁移工具已接入；服务器上线验收结果见本文末尾。

## 用户应用约束

- 普通用户仅管理自己的应用，管理员管理全部。删除普通用户时应用转交管理员。
- 上限 3 个应用，内存分配总额 768 MiB（停止的应用仍占配额）；单个 64–512 MiB、0.1–1 CPU、128 PID，无额外 swap。
- 独立 Docker 内网，宿主不发布容器端口；Go 通过运行器代理 HTTP、流式响应、WebSocket。
- 本版应用不能主动访问互联网。不提供多容器 Compose 或项目数据库编排。
- 固定非特权配置，无 host network、Docker socket 或任意宿主 bind，禁止提权并移除部分 capabilities。
- 一个可选数据目录映射到平台数据卷中的 `apps/{应用UUID}/data`；更新、重启保留，永久删除应用时清理。
- 镜像解压后上限 1 GiB；拉取时监控 Docker 磁盘，在磁盘达到 90% 或剩余空间不足时拒绝 / 中止。此空间预检不等于硬配额。2026-10-10 已迁至独立 30 GiB XFS 数据盘＋overlay2，应用可写层与持久化目录分别限制为 1 GiB，后者另限制 100000 个 inode，详情见 [磁盘配额说明](STORAGE_QUOTAS.md)。
- 每容器日志 5 MiB × 2，接口取最近 200 行、最多 256 KiB。配置变量值与仓库密码进一步遮盖。
- 环境变量、仓库密码使用与应用 ID 绑定的 AES-GCM 密文保存。迁移必须保留 `STACKNEST_AUTH_SECRET`。

适用受信任的个人 / 小团队。共享内核的 Docker 容器不提供恶意租户的强隔离。

## 更新与恢复

任务保存在 PostgreSQL，浏览器断开不影响执行。先拉镜像、创建候选容器，再停止旧容器启动候选。60 秒内等待就绪：默认检查端口；填写 HTTP 健康路径后，需要该路径返回 2xx。

部署失败时尽力恢复旧容器和配置，但**不恢复数据库结构或持久化数据**。新容器在启动阶段已经可能执行迁移或写入数据，旧程序也未必能读取变更后的数据。因此没有通用的“一键业务回退”，本版也不新增成功版本回退。破坏性数据库变更需由应用自行安排备份、兼容性检查和恢复。

新域名为 `stack-nest--app-{标识}.zby909.top`，SSH 隧道为 `stack-nest--app-{标识}.localhost:18080`，双连字符避免与现有静态项目的标识冲突。

## 健康检查与当前用量

- 表单可选填 `/health`、`/health/` 等绝对路径，不接受完整 URL、查询参数、片段或转义路径。探测只访问已确认应用的私有 IP 和容器端口，不走环境代理、不跟随重定向；每次 HTTP 请求最多两秒。
- HTTP 检查接受 200–299，3xx、4xx、5xx 和超时均失败。留空兼容旧应用的 TCP 检查，页面明确标注“端口可连接”，不把它等同于业务健康。
- 页面区分“进程运行中”和“HTTP 正常 / 检查失败”，可见时刷新 CPU、内存与进程 / 线程数。CPU 100% 表示一个核心，内存采用 Docker CLI 的 Linux 口径扣除非活跃文件缓存。
- 停止的应用不采样；采样失败或首次 CPU 增量不足时显示未知，不伪装成零。普通用户只读取自己的应用，管理员可以读取全部；接口不暴露环境变量、宿主统计或 Docker 原始返回。
- 本版不读取镜像自带的 HEALTHCHECK 结果，不自动重启 HTTP 异常的应用，不记录历史指标，不引入 Prometheus / Grafana。
- 更新健康路径会部署新一代容器；健康状态按当前容器实际的路径标签判断，避免未完成更新时使用候选配置判断旧容器。

## 使用

后台进入“Docker 应用”，填写可拉取的镜像地址及镜像实际监听的端口。镜像使用其原有 ENTRYPOINT / CMD，需要监听 0.0.0.0；仅监听 127.0.0.1 的服务不可达。第一版是单个 HTTP 容器，不在服务器编译源码，不接收镜像 tar，不提供 Compose 数据库编排。

需要保存上传文件、SQLite 等内容时填写镜像内的数据目录；该目录在更新、重启、迁移后保留。其余容器文件系统视作可丢弃内容，重建不保留。编辑时环境变量默认保持原值，不回显密文；更换同名镜像标签后点更新会重新拉取，日常启停使用已确认的镜像 ID。

应用站点内容公开，管理操作按所有者隔离。应用无法读取后台会话 Cookie，也不能向后台设置同名 Cookie 或父域 Cookie。本版没有访问码功能。

## 备份与迁移

每日备份先停止后台任务，再停止本实例正在运行的应用，打包数据库与 apps 数据目录，最后恢复原本运行的应用。停止的应用不会因备份被启动。备份期间应用短暂不可访问。

迁移包额外包含应用固定镜像及数据目录，保持原有配置密钥。新实例按数据库记录重建自己的容器、网络，不沿用旧容器 ID。导出 --freeze 会保持后台及应用停止，用于最终切换；取消冻结时先执行 runner 的 apps-thaw，再 start stacknest。

数据归档允许 apps/<UUID>/data 内的相对符号链接及指向先前文件的硬链接；绝对链接、逃逸目录的链接、设备文件、通过链接祖先写入的条目会拒绝迁移。私有仓库密码及环境变量包含在加密数据中，迁移包仍需私有保存。

迁移只保留已确认的固定应用镜像；迁移时尚未完成的部署任务会恢复重试，仍需对应镜像仓库可用。迁移后显式更新镜像也需要正确的仓库地址。

运行器要求 Linux amd64 Docker、至少 1600 MiB 宿主内存，使用 Docker API v1.45；此前在 ECS 的 Docker 29.4.3 验收，迁移后在新虚拟机 Docker 29.1.3 复验。数据硬配额另外要求 Linux 5.14+ 和 XFS 项目配额。

新服务器的本地演示镜像仓库另行迁移，只监听 `127.0.0.1:15000`，数据卷 `stacknest-smoke-registry-data`。显式更新拉取已核对；它是测试辅助服务，通用迁移工具不会自动迁移 Compose 之外的仓库。
