# Docker 应用

通过已构建镜像部署单个 HTTP 服务，当前支持 Linux amd64。用户源码构建、多容器 Compose 和镜像 tar 上传不在本功能范围内。

## 部署

进入“Docker 应用 → 部署”：

| 字段       | 填写内容                                      |
| ---------- | --------------------------------------------- |
| 镜像地址   | 如 `docker.io/用户名/应用:版本`，支持私有仓库 |
| 容器端口   | 实际端口，如 `3000`；应用需监听 `0.0.0.0`     |
| 环境变量   | 每行 `KEY=value`                              |
| 持久化目录 | 可选，如 `/app/data`，用于文件或 SQLite       |
| 健康路径   | 可选，如 `/health`，返回 2xx；留空仅检查端口  |

任务在后台执行，关闭页面不影响部署。页面显示拉取、启动和检查阶段，完成后通过应用域名访问。

镜像拉取最多等待 60 分钟；连续 5 分钟没有下载或解压进展会提前停止并说明原因。部署总时限为 70 分钟，就绪检查仍为 60 秒。拉取失败不会停止原来运行的容器，可检查网络后手动重试。

排队、准备和拉取／校验镜像时可点击“取消部署”，取消后可以修改镜像地址重新部署。开始创建或切换容器后不再接受取消。取消绑定本次任务，服务重启后也不会自动继续该次部署；已运行的版本保持服务，Docker 可能保留已下载的共享镜像层。

私有仓库凭据和环境变量以密文保存，编辑时不回显，默认保留原值。

编辑环境变量时可逐项选择保留、修改或删除，也可添加新变量。修改后留空表示空字符串；只有选择删除才移除该变量。勾选“整体替换”则以填写的列表替换全部变量。

## 数据与更新

- 仅配置的持久化目录在更新、重启和迁移后保留。
- 其他可写内容在重建后丢弃。
- 更新重新拉取镜像，启停使用已确认的固定镜像。
- 部署失败尝试恢复旧容器，但不撤销应用数据库或文件修改。
- 永久删除应用同时删除持久化数据。

数据库变更由应用自行安排备份与兼容升级，平台没有通用的业务数据回退。

## 资源限制

| 项目         | 默认值或范围                           |
| ------------ | -------------------------------------- |
| 应用数       | 默认 3 个，超管可调整                  |
| 实例内存预算 | 新安装默认 768 MiB，超管按宿主容量调整 |
| 单应用内存   | 默认 256 MiB，64–1024 MiB              |
| 单应用 CPU   | 0.1–1 核                               |
| 进程数       | 128，无额外 swap                       |
| 镜像解压大小 | 最大 2 GiB                             |
| 容器日志     | 5 MiB × 2                              |

停止或部署失败的应用仍占名额和配置内存；调整实例预算不改变已有容器额度。

拉取前按镜像上限的两倍预留处理空间，并保留至少 10% 的磁盘余量。镜像共享层与应用可写层、持久化目录分别计算；后两者的硬容量限制需启用 [XFS 配额](STORAGE_QUOTAS.md)。

## 网络与权限

普通用户管理自己的应用，管理员管理全部。应用内容默认公开。

每应用有独立网络，宿主不发布应用端口。默认不能主动访问公网；[启用联网](NETWORK_EGRESS.md)后允许公网和 Linux 本机服务，拦截其他配置的局域网地址。

应用沿用镜像 USER，可能为容器内 root；禁止 privileged、host 网络、Docker socket 和任意宿主目录挂载。[隔离原理](ARCHITECTURE.md#docker-应用隔离)

## 状态与日志

点击应用名称查看配置、健康、CPU、内存和磁盘。采样失败显示未知，不作为零。

日志展示最近 200 行、最多 256 KiB，可自动刷新并搜索当前快照。它不是完整归档，平台只遮盖已知配置值。

启动或健康检查失败时，可点击“失败详情”查看清理候选容器前保存的启动输出、退出状态、重启次数和 OOM 情况；每应用只保留最近一次失败并绑定任务代次。旧版本未保存的日志无法补回；更新失败恢复旧版后，运行日志与失败详情分别展示。
