# StackNest 需求文档

> 状态：静态部署、单容器 Docker HTTP 应用、邮箱登录、操作日志、容量保护与整机迁移已实现；部署方式和当前验证见 [检查记录](V1_REVIEW.md)。
> 定位：面向个人开发者和中小型公司的自托管私有项目部署与管理工具。

本文定义当前功能范围和验收标准。操作步骤分别见 [后端与联合部署](DEPLOYMENT.md)、[Web 构建与部署](https://github.com/zby909/stack-nest-web/blob/main/docs/DEPLOYMENT.md)；本地开发见 [Server README](../README.md) 和 [Web README](https://github.com/zby909/stack-nest-web/blob/main/README.md)。

## 1. 目标

核心目标是：

**让个人开发者和中小型公司的可信成员，在自有服务器上方便地部署、更新、查看和迁移项目。**

当前支持上传 ZIP / RAR 静态站点，以及通过已构建镜像部署单容器 Docker HTTP 应用。用户不需要为每个项目手动解压、维护 Nginx 配置或操作 Docker 命令。

### 1.1 用户与使用场景

- 个人开发者：集中管理自己的工具、演示站点、作品和小型应用。
- 中小型公司：由管理员邀请可信成员，管理内部项目、测试演示和少量业务应用。
- 实例由使用者自己部署和维护，优先支持一台 Linux 服务器及有限资源下的日常使用；规模按实际项目数量和负载判断，不以公司人数推定容量。

“私有项目管理”指自建实例和受控成员的管理范围，不代表项目访问地址自动受到保护。当前静态站点和 Docker 应用内容默认公开，预览地址也不能作为私密内容保护；需要访问控制时另行明确需求。

### 1.2 功能取舍原则

优先解决部署、更新、预览、排障、资源保护和迁移中的实际问题。易部署、易维护、易迁移，以及现有数据和项目的可靠性，优先于功能数量。

新增功能或依赖前，先说明目标用户的具体场景、现有流程的不足、最小可用方案，以及新增服务、权限、资源和维护成本；只有收益值得这些成本时才推进。讨论中的备选方案不自动成为路线图或实现承诺。

以可信成员为前提，同时保留登录和项目归属校验、敏感配置保护、容器基本隔离、资源限额及故障恢复，防范误操作、应用漏洞和资源争抢。隔离强度按实际信任边界决定，不默认按面向陌生用户的公共容器托管平台建设。

公开注册、计费、多租户商业运营、多服务器集群、Kubernetes 编排和完整监控平台不作为当前默认方向。单容器应用的数据库与数据恢复继续由应用安排，不承诺通用的一键业务回退。

## 2. 功能范围

必须支持：

- 上传 ZIP 或 RAR 静态项目。
- 通过仓库镜像部署和管理单容器 Docker HTTP 应用；范围和限制见 [Docker 应用说明](DOCKER_APPS.md)。
- 填写项目名称、可选 slug、可选说明。
- slug 留空时根据项目名自动生成。
- 项目列表与搜索。
- 打开已发布站点。
- 上传为待发布版，填写更新说明，在独立地址预览，确认后原址发布；保留上一正式版并支持确认后回退。
- 项目详情含概览、版本、文件、日志和设置，支持直接访问、刷新与前后退。
- 暂停/恢复站点访问；保留文件、地址和版本，更新与回退不自动解除暂停。
- 将完整实例导出，恢复至另一台空白服务器；操作见 [迁移文档](MIGRATION.md)。
- 删除项目及静态文件。
- PostgreSQL 持久化项目和部署记录。
- SPA fallback。
- OpenAPI 3.1，可供 Apifox 导入或 URL 同步。
- StackNest 本身支持 Docker Compose 部署。
- Nginx 统一提供管理入口和静态项目入口。
- 使用白名单邮箱接收一次性验证码登录。
- 管理员增删普通用户邮箱并管理全部项目；超管另可添加或调整管理员角色、配置实例资源预算及容器网络；普通用户只管理自己的项目。
- 添加邮箱时可选发送邀请邮件，默认不勾选；反馈添加与发信的结果。
- 查看近期上传、更新、回退、删除操作日志和磁盘余量，空间不足时禁止继续上传。

当前不做：

- 在服务器执行用户 Dockerfile / 源码构建、上传镜像 tar 或编排用户 Compose 多容器项目。
- 文件夹或 Git 仓库部署。
- 超过“当前正式版＋上一正式版＋一个待发布版”的文件保留、任意历史版本恢复、完整部署历史。
- 实时日志流、完整审计历史和综合服务器监控。
- 自助注册、密码登录、第三方 OAuth、细粒度项目权限。
- 自定义项目域名。
- 自动 HTTPS。
- 多服务器。

当前只支持一个 Go API 实例写入同一数据卷，不支持多实例共享写入。静态部署接收已经构建好的文件；Docker 部署运行已经构建好的镜像，不在服务器执行用户上传的源码或构建脚本。

> 下文的压缩包、文件版本及静态页面规则适用于静态项目；Docker 应用另见本文末尾及 [部署说明](DOCKER_APPS.md)。

## 3. 项目规则

压缩包：

- 文件最大 90 MiB（94371840 字节），代理为表单开销额外预留 1 MiB。
- 解压后累计最大 200 MiB（209715200 字节），按实际读取字节限额，不只信任压缩包声明。
- 最多 5000 个条目，包含文件和目录条目。
- ZIP 目录索引解析最多读取 8 MiB 元数据，正文仍按归档和解压限额处理；异常庞大的目录或注释会被提前拒绝。
- 不允许路径穿越、软链接、硬链接及特殊文件。
- RAR 仅支持未加密的单卷文件；解码字典最大 64 MiB。
- 根目录或唯一一级目录必须包含 `index.html`。

磁盘保护：以数据目录所在文件系统对应用可用的空间为准，已使用达到 90% 或加上本次处理预算后达到 90% 时，在读取上传正文前拒绝请求。第一版按最坏情况预留 412 MiB（两份归档、解压内容和 32 MiB 开销），接收、解压、发布阶段继续复查。容量不足返回 507，磁盘探测失败返回 503；同一时刻只处理一个上传，其他请求返回 429。失败清理临时文件，重启也会恢复中断操作。

slug：

- 长度 1-52 个字符，为站点域名的 `stack-nest-` 前缀预留 11 个字符，保证单个 DNS 标签不超过 63 个字符。
- 只允许小写字母、数字和连字符。
- 不能以连字符开头或结尾。
- 用户手填时严格校验，不自动修改。
- 留空时才根据项目名生成。
- 名称无法提取字母或数字时（如纯中文名称），自动生成 `project-<UUID>`，无需手填 slug。
- slug 重复返回冲突，用户需修改名称或手填其他 slug；不自动追加编号。

上传内容示例：`index.html + assets/`，或 `dist/index.html + dist/assets/`。React/Vite 项目应先在本地构建，再压缩 `dist`；只有源码、没有 `index.html` 的压缩包不符合要求。

创建成功后才加入列表，并保存一条成功部署记录。上传失败时在创建弹窗内显示原因并保留表单，操作日志保存成功与失败结果；日志不是完整版本历史。删除需二次确认，失败时在删除弹窗内显示原因。

更新与回退：

- 普通用户只更新或回退自己的项目，管理员可以操作全部项目；项目 ID、所有者、slug、名称、说明和地址不变。
- 新建和更新均先保存一个待发布版，沿用容量、归档安全检查，支持可选更新说明（最多 4096 个 UTF-8 字节）。上传与预览不改变正式版；用户确认发布后用同卷目录重命名切换，可能存在极短的请求失败窗口，不承诺零停机。
- 最多保留当前和上一正式版，另允许一个待发布版。新草稿发布后清理更早正式版；已有草稿时需先发布或丢弃，不能覆盖草稿或回退正式版。失败尝试另存操作日志。
- 回退前展示上一版文件名和发布时间并确认；回退后原当前版成为新的上一版，可再回退一次撤销操作。
- 上传草稿、确认发布和回退均校验当前正式版编号；发布、丢弃另校验确切草稿编号。页面版本过期返回 409，需刷新后再操作，防止旧页面覆盖新版本。
- 文件切换与数据库事务之间保留恢复标记；进程中断后根据数据库部署编号完成或撤销切换。结果无法确认时保留文件，禁止该项目继续写入，重启恢复后再操作。
- 回退只移动已有文件，不占用整份上传处理预算，暂停上传时仍可尝试回退；磁盘完全写满等文件系统故障仍可能导致操作失败。
- 删除项目同时删除当前、上一版与草稿。每个保留版本有独立预览地址；发布和回退不改变版本编号，清理后旧地址返回 404。预览持有地址即可访问，不能作为私密文件保护。暂停同时关闭全部预览。
- 版本页可比较新增、修改和删除文件，内容摘要可识别大小不变的修改；不提供在线编辑。

## 4. 页面

项目名称与说明可由所有者或管理员在“更多 → 编辑信息”中修改，slug、网址、归属和文件不变。名称的 UTF-8 编码最多 256 字节，说明最多 4096 字节；说明留空可清除。保存携带项目更新时间，过期页面不能覆盖新编辑或发布，需刷新列表后重试。

“更多 → 导出 ZIP”可下载草稿、当前版或仍保留的上一版，包含已经解压并部署的静态文件；不包含原始上传归档或项目源代码仓库。RAR 上传也导出为 ZIP。导出校验部署编号，失效时返回 409；打包期间与发布串行，下载期间可以继续更新。最多 200 MiB、5000 个文件；ZIP 临时空间预算 216 MiB，磁盘 90% 规则同样生效。单实例同时只处理一个导出，最多 10 分钟，支持取消；连接结束清理快照，启动时清理中断残留。

管理端有登录、项目、操作日志和管理员专属的用户邮箱界面。管理员可查看全部项目与操作日志，普通用户只可查看自己的项目及相关日志。

登录邮箱在首次启动、用户表为空时由配置导入；后续由管理员在界面增删普通用户。新增邮箱默认不发送邀请，管理员可在本次添加前勾选“发送邀请邮件”；添加成功后复位为不勾选。邀请仅包含固定 HTTPS 登录地址与验证码登录说明，不生成验证码、会话或自动登录链接。地址来自 `STACKNEST_INVITATION_LOGIN_URL` 或管理域名，页面显示即将使用的地址；未配置可用地址时不能发邀请，但仍可添加邮箱。重复邮箱或无效请求不会发信；SMTP 失败或超时仍返回添加成功并保留用户，单独提示邀请未能确认发送。SMTP 接受邮件不保证进入收件箱。持有人知道登录地址后即可请求验证码。管理员邮箱不能通过界面删除。普通用户可以查看、上传和删除自己的项目，但不能查看或修改邮箱名单；管理员可管理全部项目。移除普通用户后，其已有会话立即失效，其项目在同一数据库事务内转交管理员，站点文件和公开地址保持可用。

项目归属保存在 PostgreSQL 的 `projects.owner_user_id`，关联登录用户 ID；上传时由服务端会话决定归属，浏览器不能指定。既有项目在迁移时归管理员。站点文件仍以全局唯一 slug 存放，不靠目录或邮箱判断所有权。公开的静态站点 URL 不要求登录，不适合存放私密内容。

验证码为 8 位数字，10 分钟有效且只能使用一次；同一邮箱 60 秒内最多发送一次，连续 5 次错误后本次验证码失效。验证码和会话令牌在数据库中只保存摘要。登录会话保存在 HttpOnly、SameSite=Strict Cookie 中，7 天后过期，可主动退出。HTTPS 使用 `__Host-stacknest_session`、`Secure`、`Path=/` 且不设置 `Domain`，防止上传站点通过父域同名 Cookie 干扰后台会话；HTTPS 不接受旧名称。仅本地 HTTP 开发或 SSH 入口继续使用 `stacknest_session`。

页面包含：

- 当前用户可管理的项目总数和开放访问项目数；这是数据库中的发布状态，不代表实时可用性监控。
- 按名称、slug、说明搜索，忽略英文大小写；当前在前端过滤已加载列表，无分页。
- 项目列表。
- “部署静态项目”按钮。
- 磁盘总容量、可用容量、使用比例和暂停上传原因；项目页每 30 秒刷新，并可手动刷新。
- 普通用户只看到上传暂停原因和“重新检查”按钮，不显示磁盘容量或使用率；首次加载显示检查中。检查失败时禁用上传及更新，容量接口等待最多 10 秒；删除和上一版回退不受上传暂停限制。
- 操作日志：服务端先按身份与条件筛选全部保留记录，再分页并计算总数，每页 20/50/100 条。可组合项目标识、操作类型、结果、操作人邮箱、日期和关键词；关键词匹配项目、文件、邮箱、请求编号及原因。日期按设备时区计算，包含结束日。普通用户可见自己执行或作用于自己项目的记录；旧日志缺用户 ID 时仅管理员可见。日志自动轮转，删除项目不删除已有记录，轮转清理的历史不在查询范围。
- 管理员的服务器状态页包含备份摘要：最近成功时间、数据库与站点备份大小、保留份数和总大小，以及最近任务结果。任务失败时仍显示之前的成功记录；超过 45 分钟仍在运行提示可能中断，超过 48 小时无新成功备份提示检查。未配置、尚无记录及读取失败均明确显示，不假报成功。普通用户不可读取此接口，API 仅只读挂载摘要目录，不访问备份原文件或 Docker socket。

项目列表展示：

- 名称。
- slug / 说明。
- 发布状态。
- 最近上传文件名。
- 最近更新时间。
- 草稿、当前版和上一版的逻辑文件大小与文件数；列表只显示合计，详情通过图标悬浮、聚焦或点按查看，未保留的版本显示“无”。
- 按最新更新时间、保留版本合计占用升序或降序排列，可刷新统计；无法读取的版本显示“统计暂不可用”，合计不按零计算，容量排序始终排后。
- 所属邮箱（仅管理员界面）。
- 打开站点。
- 更新；编辑、导出、回退与删除位于“更多”菜单，尚无上一版时回退禁用。
- 删除。

统计仅覆盖保留版本的普通文件，不包括原始压缩包、临时目录、数据库、日志或备份，也不代表文件系统分配的磁盘块数。沿用项目归属权限，普通用户只能查看自己项目的统计；全服务器容量仍仅管理员可查看。无需数据库迁移。

创建弹窗：

- 项目名称：必填。
- slug：可选。
- 项目说明：可选。
- 版本更新说明：可选，按纯文本保存与展示。
- ZIP 或 RAR：必填。
- 文件传输进度与服务端处理提示；完成前防止重复提交。登录验证码显示 60 秒重发倒计时。

UI 实现入口为 [App.tsx](https://github.com/zby909/stack-nest-web/blob/main/src/App.tsx)，主题与全局样式位于 [index.css](https://github.com/zby909/stack-nest-web/blob/main/src/index.css)，复用组件位于 `web/src/components/`。桌面和手机均需可用，表单和错误提示不能被遮挡或产生横向溢出。

早期 HTML 设计稿仅为归档参考，不作为功能验收标准。

## 5. 生产架构

```text
管理入口（登录保护） / 项目访问入口（公开）
   |
   v
Nginx (web 构建产物 + 静态项目)
   |------> /data/sites/{slug}
   |
   +-- /api/ --> StackNest Go
                       |
                       v
                   PostgreSQL
```

Docker Compose 包含：

- `nginx`
- `stacknest`
- `postgres`
- `migrate`

Nginx 使用固定泛域名配置读取共享静态文件。新增项目不生成 Nginx server block，也不 reload Nginx。

例如管理端为 `stack-nest.zby909.top`，项目基础域名为 `zby909.top`，slug 为 `demo` 的站点地址是 `stack-nest-demo.zby909.top`。生产项目从域名根路径提供资源，缺失路径回退到该项目的 `index.html`。本地与 SSH 使用 `stack-nest-demo.localhost` 和当前入口端口提供隔离预览，管理主机禁止 `/sites/`，预览主机禁止管理 API。其他域名即使被泛 DNS 解析到服务器，也不会映射为项目 slug。

## 6. API

唯一接口契约为 [openapi/openapi.yaml](../openapi/openapi.yaml)，可导入 Apifox。管理端详情使用单个项目接口与版本、文件、日志接口；服务端仍逐项校验归属。

| Method | Path                                 | 用途                                                                      |
| ------ | ------------------------------------ | ------------------------------------------------------------------------- |
| GET    | `/api/health`                        | API 与数据库连接就绪检查；2 秒超时，正常 200，异常 503；不探测站点或 SMTP |
| POST   | `/api/auth/request-code`             | 请求一次性登录验证码                                                      |
| POST   | `/api/auth/verify`                   | 验证邮件验证码并建立会话                                                  |
| GET    | `/api/auth/session`                  | 查询当前会话                                                              |
| POST   | `/api/auth/logout`                   | 退出登录                                                                  |
| GET    | `/api/projects`                      | 可管理的项目列表                                                          |
| GET    | `/api/storage`                       | 数据盘余量、上传限制与准入状态                                            |
| GET    | `/api/activity`                      | 可见的最近项目操作日志                                                    |
| POST   | `/api/projects`                      | 上传并部署                                                                |
| GET    | `/api/projects/{slug}`               | 项目数据                                                                  |
| PATCH  | `/api/projects/{slug}`               | 原址编辑项目名称和说明                                                    |
| GET    | `/api/projects/{slug}/export`        | 按部署编号导出当前版或上一版 ZIP                                          |
| POST   | `/api/projects/{slug}/draft/publish` | 确认发布指定草稿并轮转正式版本                                            |
| DELETE | `/api/projects/{slug}/draft`         | 丢弃指定草稿，保留正式站点                                                |
| GET    | `/api/projects/{slug}/changes`       | 比较保留版本的文件变化                                                    |
| DELETE | `/api/projects/{slug}`               | 删除项目                                                                  |
| GET    | `/api/users`                         | 管理员查询邮箱名单                                                        |
| GET    | `/api/backups/status`                | 管理员查询最近备份结果与体积                                              |
| POST   | `/api/users`                         | 管理员添加普通用户邮箱；超管可添加管理员，可选发送邀请                    |
| DELETE | `/api/users/{id}`                    | 管理员移除普通用户邮箱                                                    |
| GET    | `/openapi.yaml`                      | OpenAPI 文档                                                              |

HTTP 路由和响应模型由 oapi-codegen 从 OpenAPI 生成。

API 0.5.0 新增 `PATCH /api/projects/{slug}`（`If-Match` 为带引号的 `updatedAt`）、`GET /api/projects/{slug}/export?deploymentId=...` 及管理员的 `GET /api/backups/status`。编辑及导出不改变数据库结构，无新增迁移。

API 0.6.0 增加 `PUT /api/projects/{slug}/access`，请求为 `{ "paused": true/false }`，`If-Match` 为带引号的 `updatedAt`；按归属和版本校验。暂停后本地预览和 Nginx 的页面与资源返回 503；更新、回退、导出仍可操作，数据库保存状态，站点目录之外的标记约束 Nginx，重启恢复。无法撤回已下载或缓存的内容，不能代替私密文件权限控制。

`GET /api/activity` 接受 `page/pageSize/slug/action/status/actor/q/from/to`，返回 `events/total/page/pageSize`。登录、管理页面和低频弹窗按需加载，下载失败提示手动刷新。无新增数据库迁移。

## 7. 安全边界

已处理：

- 上传大小限制。
- ZIP/RAR 路径穿越、链接、文件数量和解压大小。
- PostgreSQL 唯一约束与事务。
- 数据库版本化 migration。
- 删除先暂存站点目录，数据库失败时恢复；启动时恢复或清理上次中断的删除。
- 上传先保存进行中标记，重启时根据数据库状态保留已成功站点或清理未提交文件；数据库结果未知时保留现场，不盲删。
- 日志不记录验证码、授权码、Cookie、请求正文或带查询参数的 URL。
- Nginx 对静态项目 volume 只读。
- Go 层对项目 API 验证服务端会话，对邮箱管理 API 再验证管理员角色。
- 项目读取和删除按会话用户 ID 校验所有者，越权读取/删除返回 404；删除前后均检查归属，避免转交并发时误删文件。
- 邮件验证码短时有效、一次性使用、错误次数与请求频率受限；写接口校验同源 Origin / Referer。
- 浏览器会话仅放在 HttpOnly Cookie 中，退出和移除用户都会在数据库中撤销会话。

当前不自动签发 HTTPS 证书。普通公网使用可信 HTTPS 证书；Cloudflare 普通代理另用 Full (strict)，家用 Tunnel 不需要本机证书。本地仍可通过 SSH 隧道访问，入口见部署文档。项目站点会公开提供，压缩包校验不负责清除其中的敏感内容或验证网页脚本安全性。SMTP 授权码、源站私钥及验证码摘要密钥仅放在服务端私有配置中，不进入 Web 构建产物。

## Docker 应用（API 0.10.0）

普通用户可部署与管理自己的单容器 HTTP 应用，管理员可管理全部。输入仓库镜像地址、容器端口、环境变量、CPU / 内存及一个可选数据目录，支持私有仓库凭据、部署、启停、重启、更新、日志和永久删除。后台持久化任务，页面关闭不取消部署。

先拉取镜像再切换，60 秒内未满足端口或配置的 HTTP 就绪要求则尽力恢复旧容器；应用自身对持久化数据的修改不回退。密码和变量值不回显，访问内容公开，管理会话 Cookie 不传给应用。版本首版不提供源码构建、镜像 tar 上传、Compose 或访问码。默认网络为 internal，可选启用公网和宿主服务访问并拦截其他局域网设备。限制与验收见 [Docker 应用说明](DOCKER_APPS.md)。

Docker 应用实例预算由超管在界面维护，默认 3 个应用、总内存 768 MiB；停止的应用仍预留额度。配置有版本检查，不允许小于当前预留值，运行器核对宿主安全上限。普通用户仍只能管理自己的应用。任务卡片显示实际阶段和已知镜像层下载量，刷新可继续观察；最终任务结果持久化，阶段快照不承诺跨 Runner 重启保留。

Docker 应用详情使用 `/apps/<id>` 和 `/apps/<id>/logs` 独立路由。展示运行状态、非敏感配置、可写层与持久化数据用量；XFS 块计数每分钟采样，达到空间或 inode 配额 90% 显示提醒。日志支持自动刷新、暂停跟随和当前快照搜索，不承诺完整历史。部署自检见 [首次部署与自检](GETTING_STARTED.md)。

超管可调整现有普通用户和管理员的角色，要求确认及原角色匹配；成功后撤销目标用户的所有会话和验证码，记录操作日志，不转移项目，不发送邀请。部署指定的管理员和超管不可调整角色。

超管添加邮箱时可明确选择“管理员”，每次默认普通用户，邀请发送默认关闭。普通管理员只能添加普通用户；重复新增不能将已有普通用户升级，接口不能授予超管，现有管理员不可通过邮箱删除接口移除。新增管理员可管理全部项目、普通用户邮箱及查看服务器状态；网络与实例预算配置仍专属超管。
